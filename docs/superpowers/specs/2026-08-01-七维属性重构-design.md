# 七维属性重构设计（PAC/SHO/PAS/DRI/DEF/PHY/WIL）

日期：2026-08-01
状态：待实施
影响文件：`app.js`、`style.css`、`index.html`、`tests/structure.test.mjs`、`README.md`

---

## 0. 背景与目标

### 0.1 现状的三个问题

1. **属性分两层，语义重叠**。`stats`（身高/速度/爆发/耐力/意志）与 `skills`（射术/盘带/视野/定位球）是两套独立数值、两个成长函数（`gainStat` / `gainSkill`）、两条软上限曲线。玩家看不到 `skills`——首页只显示 5 个 `stats`，而射术这个前锋最核心的能力反而藏在生涯页。
2. **状态与体能的影响散落各处**。`momentSuccessRate` 里是 `+s.form/1000+s.fitness/2000`，`prepareMatch` 里是 `+(s.form-50)/260`，`weightedStatScore` 里是 `+s.form*.18+s.fitness*.12`——三个地方三套系数，加一处新判定就得重新拍一次脑袋。
3. **变量职责重叠**。心情（`morale`）与状态（`form`）都表示"最近状态好不好"，都进 `weightedStatScore`；教练信任、关系值、队内适应也都掺在同一个战力公式里。玩家无法建立"我改变 X 会导致 Y"的心智模型。

### 0.2 目标

- 属性收敛成**唯一一层七项**，与 FIFA 缩写对齐，首页七边形雷达图直接展示
- 所有行动、比赛结果、进球判定**只经由这七项**发生，状态与体能作为统一的动态系数介入
- 每个变量**只承担一件事**

### 0.3 六项改动与本文档章节

| # | 用户需求 | 章节 |
|---|---|---|
| 1 | 身高不在首页作为主属性展示 | §1.4、§5.1 |
| 2 | 主属性改为七项 | §1 |
| 3 | 所有行动与比赛判定对应这七项，并考虑状态/体能 | §2、§3 |
| 4 | 首页七边形雷达图（FIFA 风格） | §5.1 |
| 5 | 小满互动影响意志/状态/体能 | §3.3 |
| 6 | 缩小「本场风格」框 | §5.3 |

## 1. 数据模型

### 1.1 属性表

`ATTRS` 是唯一真源，取代 `CORE_STATS` 与隐式的 skills 列表：

```js
const ATTRS=[
  {key:"PAC",name:"速度",sub:"冲刺与启动",icon:"»",w:.21},
  {key:"SHO",name:"射门",sub:"终结与打门",icon:"◎",w:.25},
  {key:"PAS",name:"传球",sub:"视野与定位球",icon:"▣",w:.08},
  {key:"DRI",name:"盘带",sub:"控球与过人",icon:"✦",w:.14},
  {key:"DEF",name:"防守",sub:"逆抢与协防",icon:"▰",w:.05},
  {key:"PHY",name:"身体",sub:"对抗与续航",icon:"▲",w:.13},
  {key:"WIL",name:"意志",sub:"抗压与临场",icon:"◆",w:.14}
];
```

状态字段：`s.attrs = {PAC,SHO,PAS,DRI,DEF,PHY,WIL}`，删除 `s.stats` 与 `s.skills`。

`overall(s)` = `ATTRS` 的 `w` 加权和（权重合计 1.00）。

**权重按前锋定**：SHO + PAC 占 46%。DEF 只占 5%——它不应虚抬卡面 OVR，但通过 §2.3 的球队贡献分实打实影响胜负。这个"低卡面权重 / 高实战权重"的错位是刻意设计：防守对前锋的价值不在数据面板上。

### 1.2 成长函数

`gainStat` 与 `gainSkill` 合并为单个 `gain(s, key, n, tag)`。合并后需保留原 `gainSkill` 中的两个特例：

- `s.flags.outOfPosition` 时 SHO 成长 ×0.7（国家队改踢边翼卫的后果）
- 天赋倍率按 §1.5 的新 tag 表匹配

### 1.3 存档迁移（`VERSION 2 → 3`）

读档时执行一次 `migrateV2toV3(save)`：

| 新属性 | 由旧值计算 |
|---|---|
| PAC | `(speed + burst) / 2` |
| SHO | `finishing` |
| PAS | `vision*.65 + setPiece*.35` |
| DRI | `dribble` |
| PHY | `(height + stamina) / 2` |
| WIL | `will` |
| DEF | `20 + stamina*.35 + will*.15` |

DEF 无旧值对应，按耐力与意志推算一个偏低的起点——前锋本来就没练过防守。

同时迁移：`form = round(form*.65 + morale*.35)`（见 §1.6），删除 `morale` 字段，`allocation` 字段整体废弃（仅创建时使用，见 §5.4）。

**OVR 漂移验算**（五种 build，覆盖生涯两端）：

| build | 旧 OVR | 新 OVR | 差 |
|---|---|---|---|
| 新手 14 岁 | 55 | 53 | −2 |
| 均衡型（h58 s70 b72 st65 w68 / f72 d64 v55 sp48） | 67 | 66 | −1 |
| 支点型（h82 s55 b58 st78 w75 / f76 d52 v50 sp45） | 67 | 66 | −1 |
| 速度型（h45 s85 b88 st62 w60 / f70 d80 v52 sp40） | 70 | 69 | −1 |
| 巅峰 32 岁 | 87 | 86 | −1 |

全部在 ±2 内。**存在 −1 的系统性偏差**（新权重把旧的 `burst .18` 拆进了 PAC 的 `.21`，整体略保守）——这是可接受的，不加补偿常数：玩家看到 OVR 掉 1 点比看到属性表被硬凑更容易接受，且新档不受影响。由 §6 的测试卡住上界。

**迁移失败的处理**：`migrateV2toV3` 包在 try/catch 里。若抛错或产出任何 `NaN`，回退到"提示玩家本次更新重构了属性系统、需要重开"并清档，而不是让损坏的存档进入游戏。

### 1.4 身高

`heightCm` 保留为背景数值，新增 `heightTier`（`"short" | "mid" | "tall"`）。

- 创建时**独立选择**，不占分配点
- 高个：PHY 初值与成长 +，PAC/DRI 成长 −
- 矮个：相反
- 首页不再展示；移到生涯页档案

现有 `growth_pain` 事件（"一个夏天你突然长高了六厘米"）里对 `gainStat(s,"height",2)` 的调用改为 `gain(s,"PHY",2)`，`s.heightCm` 的增减保留。

### 1.5 天赋 tag 重映射

| 天赋 | 旧 tag | 新 tag |
|---|---|---|
| 一步先机 | burst | PAC / DRI |
| 禁区嗅觉 | finish | SHO |
| 大心脏 | will | WIL |
| 空霸 | height | PHY |
| 任意球专家 | setpiece | PAS |
| 逆足精通 | finish/dribble | SHO / DRI |
| 绿茵领袖 | will | WIL |
| 高球商 | vision | PAS |
| 永动机 | stamina | PHY + 体能 |
| 铁人 | injury | 不变 |

### 1.6 变量职责表

重构后每个变量只承担一件事：

| 变量 | 只管这一件事 |
|---|---|
| 七项属性 | 场上表现的基底 |
| 状态 `form` | `cond()` 的一半（吸收原「心情」） |
| 体能 `fitness` | `cond()` 的另一半 |
| 教练信任 `coachFavor` | 首发概率 |
| 小满关系 `relationship.love` | 抬高状态基线 + 剧情门槛 |
| 队内适应 `teamFit` | 保持现状，仍作为首发概率的次要输入 |

**心情彻底删除**。25 处 `change(*,"morale",n)` 全部转成 `change(*,"form",round(n*0.6))`。系数 0.6 的理由：原心情改动幅度最大到 +18，而 `form` 每月有 22% 回归基线，1:1 搬运会让状态过山车。两处 −4 变成 −2。同时删除侧栏「心情」行与 `moraleText`/`moraleBar` 两个 DOM 节点。

**小满关系改为抬高状态基线**（原先它藏在 `weightedStatScore` 里当隐形战力加成）：

```js
// 月度结算：状态回归基线，基线由小满关系抬高
const base = 52 + loveSupport(s);        // 关系 85+ → 基线 59；分手 → 52
change(S,"form", Math.round((base-S.form)*0.22))
```

关系好不再是"+7 战力"，而是"长期状态更稳"。分手的代价从此在状态曲线上看得见。

`loveSupport(s)` 函数本身不变（返回 0/1/3/5/7），只是调用点从 `weightedStatScore` 移到月度结算。

## 2. 判定内核

### 2.1 有效属性

```js
// 状态系数：状态与体能共同决定，基准点取中局典型值 (form 55 / fitness 72)
function cond(s){ return clamp(1 + (s.form-55)/500 + (s.fitness-72)/600, .78, 1.08) }

// 分属性敏感度
const COND_SENS={PHY:1.4, PAC:1.3, DEF:1.2, DRI:1.0, SHO:.7, PAS:.6, WIL:.4};

// 有效属性：所有判定的唯一入口
function eff(s,k){ return s.attrs[k]*(1+(cond(s)-1)*COND_SENS[k]) }
```

**任何判定不得直接读 `s.attrs[k]`**，一律经由 `eff()`。UI 展示读裸值。

敏感度的效果：体能见底（`cond=.78`）时 PHY 70 → 48，WIL 70 → 64。累垮的是身体，不是意志。这让体能管理产生战术意义——体能低的下半场，玩家应主动选依赖 SHO/WIL 的关键时刻选项，而不是硬拼 PAC。

### 2.2 双重计数（本次重构最大的坑）

`eff()` 已经把状态与体能吃进去了。旧公式里每一处 `form/1000`、`fitness/2000`、`(form-50)/260`、`s.form*.18`、`s.fitness*.12` **必须删干净**，否则状态好时强度会失控。

需要逐个核对的位置：`momentSuccessRate`、`prepareMatch` 的射门尝试循环、`prepareMatch` 的 `rawStart`、`weightedStatScore`（整体删除）。

### 2.3 球队贡献分

```js
atk(s) = eff(s,"SHO")*.35 + eff(s,"PAC")*.25 + eff(s,"DRI")*.20 + eff(s,"PAS")*.20
def(s) = eff(s,"DEF")*.60 + eff(s,"PHY")*.25 + eff(s,"WIL")*.15
```

`weightedStatScore` 删除，由这两个函数取代。

### 2.4 四层判定改法

| 判定 | 现状 | 改成 |
|---|---|---|
| 比赛结果 | `weightedStatScore` 掺 form/fitness/morale/信任 | `clubEdge += (atk−队伍强度)*.14 + (def−队伍强度)*.06` |
| 逼抢职责 | 固定 `clubEdge += 2.5` | `clubEdge += (def(s)−55)*.10` |
| 射门尝试 | `.25+(stat−45)/90+(form−50)/260+天赋` | `.25+(eff(主属性)−45)/90+天赋` |
| 进球转化 | `.38+(stat−52)/100+goalBonus` | `.38+(eff(s,"SHO")−52)/100+goalBonus` |
| 助攻转化 | `.26+(vision−45)/150+assistBonus` | `.26+(eff(s,"PAS")−45)/150+assistBonus` |
| 关键时刻 | `.35+(stat−opp)*.008+form/1000+fitness/2000` | `.35+(eff(s,o.stat)−opp)*.008` |

**后三层刻意保留原有的常数与除数**（45/90、52/100、45/150、.008），只替换取值来源并删掉 form/fitness 散项。这样平衡漂移只来自 `eff()` 一个变量，出问题时容易定位。各自的 `clamp` 区间不变：射门尝试 `.16–.88`、进球转化 `.28–.82`、助攻转化 `.18–.63`、关键时刻 `.15–.85`。

`goalBonus` / `assistBonus`（职责与流派修正）沿用现状，不动。

**射门类型 → 属性映射**（`prepareMatch` 的 `types` 循环）：

| type | 属性 |
|---|---|
| finish | SHO |
| dribble | DRI |
| header | PHY |
| setpiece | PAS |
| pass | PAS |

`MOMENTS` 中每个选项的 `o.stat` 从旧 key（`finishing`/`dribble`/`vision`/`setPiece`/`height`/`burst`）改写为七项之一。`aerial_duel` 的 `cond` 从 `s.stats.height>=60` 改为 `s.attrs.PHY>=60`。

### 2.5 逼抢职责变成有条件的选择

`(def(s)−55)*.10` 意味着 DEF 相关贡献低于 55 时选逼抢是**净负收益**——白跑还掉体能。这比现状的无脑 +2.5 更有取舍，也给新的「前场逆抢」训练提供了明确的投资回报。

首发概率 `rawStart` 保留 `coachFavor`、`teamFit`、`overall`，删除 `form` 项（状态已经通过 `eff` 影响场上表现，不应再影响是否首发）。

|---|---|---|---|---|---|

### 3.4 流派 → 属性软上限

流派等级抬高对应属性的成长天花板，每级 +5：

```js
function softFactor(cur,d,lv){
  const t=lv*5;
  let f = cur>=88+t?.25 : cur>=82+t?.4 : cur>=75+t?.6 : cur>=68+t?.8 : 1;
  if(cur>=68+t) f/=d.soft;
  return f;
}
```

| 流派 | 抬高谁的上限 |
|---|---|
| 禁区杀手 | SHO |
| 爆点前锋 | PAC · DRI |
| 支点中锋 | PHY · DEF |
| 组织型前锋 | PAS |

没有流派兜着的属性练到 88 左右基本爬不动；Ⅲ 级禁区杀手才能把 SHO 真正推过 95。

**WIL 不归任何流派**——它只从剧情选择、压力事件和小满那里长，练不出来。这与它在 `COND_SENS` 里最抗跌（.4）互为呼应：意志是唯一不被身体状况打折的东西。

流派卡面标注属性缩写（如「禁区杀手 · SHO」），与雷达图对应。流派数量保持 4 条，不新增。

## 4. 不做什么（YAGNI）

- **不新增第五条流派**。前场逆抢训练计入既有的支点中锋流派。
- **不做位置系统**。玩家仍是前锋，DEF 的价值通过逆抢与团队贡献体现，不解锁改踢其他位置。
- **不合并教练信任与小满关系**。两者驱动完全不同的剧情线；合并会产生"教练不高兴导致女友分手"的荒谬因果，且分手/复合/求婚/结婚 9 个门槛需重新设计。
- **不重构 `teamFit`**。它工作正常，只是不露脸；本次不动。

## 6. 测试

### 6.1 现有测试必然变红

`tests/structure.test.mjs`（178 行）中一批断言直接读 `state.skills.finishing`、`state.skills.setPiece`、`state.allocation` 合计 20、`"clutch" in state.skills`。这些**需要跟着改写，不是删掉**——它们保护的语义（技术属性是真实数值、关键球不设独立数值）在新模型下依然成立，只是载体从 `skills` 变成 `attrs`。

### 6.2 新增断言

1. **迁移**：三种典型 build 跑 `migrateV2toV3`，OVR 漂移 ≤ 2，七项全在 1–99，无 `NaN`
2. **无双重计数**：固定属性，`form` 从 30 拉到 90，`momentSuccessRate` 涨幅落在预期区间
3. **敏感度方向**：`cond` 下降时 PHY 跌幅 > WIL 跌幅
