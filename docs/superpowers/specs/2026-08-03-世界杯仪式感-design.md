# 世界杯仪式感设计（点球大战 / 人物节点 / 夺冠与淘汰）

日期：2026-08-03
状态：待实施
影响文件：`app.js`、`tests/structure.test.mjs`

---

## 0. 背景与目标

### 0.1 问题

**世界杯比赛比一场普通联赛还要没得玩。**

俱乐部比赛有 `timeline` 逐分钟文字，外加两个**关键时刻**让玩家选择——成功率由属性驱动，有高风险/稳妥的取舍，打出来还能留下「经典之战」。整个流程挂在可序列化的 `pendingMatch` 上，刷新页面不丢。

世界杯比赛的全部产出是一个比分：

```js
return {opp,strength,gf,ga,goals,assists,won,pen,mentality,stage}
```

七场比赛，七个弹窗，每个写着「中国 2-1 X，你贡献 1 球」。游戏的最高潮，玩家参与度低于一个周二的联赛轮次。

三个具体缺口：

1. **点球大战是一次隐藏掷骰**。`if(i>=3&&gf===ga){pen=true;won=rng()<clamp(.42+edge/40+...)}` —— 足球里最有仪式感的场面，玩家看都看不见。
2. **全程没有人**。小满、父亲、周骁的立绘都是现成的，世界杯里一个都没出现。这款游戏最强的是人物。
3. **世界杯刷新即消失**。读档时 `if(S.national&&S.national.wcRun)S.national.wcRun=null;` 无条件清空进行中的世界杯。

### 0.2 目标

补上「紧张」与「在乎」两种感觉，并让新的七维属性体系里最没有舞台的 **WIL（意志）** 第一次被玩家真切感知。

### 0.3 本次范围

做：点球大战交互化、人物固定节点、夺冠与淘汰仪式、`wcRun` 可恢复。

不做（留待独立一轮）：世界杯比赛接入 `MOMENTS` 关键时刻系统、小组赛加入基调选择。这两项需要把世界杯搬到 `pendingMatch` 引擎上，工程量与风险高一档。

## 1. 架构：wcRun 可恢复

### 1.1 为什么必须先做这个

点球大战是多步交互。若不持久化，玩家在第四轮刷新页面，**整届世界杯消失**——比现状更伤，因为加了仪式感之后玩家更舍不得那届世界杯。

俱乐部比赛已经解决过同一个问题：`pendingMatch` 是纯 JSON，且测试锁住了「待决比赛必须能存档」。世界杯照抄这套纪律即可。

### 1.2 改动

- 删除读档路径里的 `if(S.national&&S.national.wcRun)S.national.wcRun=null;`
- 读档后若 `S.national.wcRun&&S.national.wcRun.alive`，按 `wcRun.stage` 与 `wcRun.shootout` 重新入场
- `wcRun` 及其新增的 `shootout` 子状态必须是纯 JSON：不含函数、不含 `undefined`

现有的 `saveGame()` 在每次弹窗选择应用后都会调用，因此只要状态是可序列化的，持久化就是自动的。

## 2. 点球大战

### 2.1 状态

```js
run.shootout={
  round:1,          // 当前轮次 1..5，>5 进入突然死亡
  myScore:0,
  oppScore:0,
  kicks:[],         // [{side:"me"|"opp",round,scored,text}]
  myRound,          // 玩家在第几轮主罚，由 WIL 决定
  sudden:false,
  done:false
}
```

### 2.2 玩家在第几轮主罚，由意志决定

| WIL | 主罚轮次 | 语义 |
|---|---|---|
| ≥75 | 第 5 轮 | 教练把决定命运的一脚交给你 |
| 55–74 | 第 3 轮 | 中段 |
| <55 | 第 1 轮 | 先踢，卸掉压力 |

判定用裸 `WIL`（不经 `eff()`）——这是赛前的教练决策，取决于你是什么样的球员，而不是此刻多累。

### 2.3 队友罚球

成功率由国家队实力决定：

```js
const teamStrength=74+(overall(s)-72)*.72+(s.national.adapt||0)*.06;
const p=clamp(.72+(teamStrength-74)/200,.55,.88);
```

对手罚球同理，用 `opp.strength` 代入。逐轮推进，每轮亮出比分板。

### 2.4 轮到玩家：三选一

| 选择 | 属性 | 基础成功率 | 附加 |
|---|---|---|---|
| 抽死角 | **SHO** | `.58+(eff(s,"SHO")-70)/200` | 成功：声望 +4，标记「经典一脚」；失手：打飞，收尾文案更狼狈 |
| 稳稳推一侧 | **SHO** | `.68+(eff(s,"SHO")-70)/160` | 无 |
| 等门将先动 | **WIL** | `.68+(eff(s,"WIL")-70)/300` | 对体能最不敏感 |

全部 `clamp` 在 `.35`–`.92`。`big_heart` 天赋在点球大战 +.06（与它现有的「点球大战表现更稳」描述一致）。

**为什么「抽死角」成功率更低却依然值得选**：点球是二元结果，若三个选项只有成功率差异，最高的那个必然严格占优，另外两个就是死选项。所以「抽死角」的价值不在概率而在**附加**——成功留下会被记住的一脚，失手则连收尾文案都更难看。这与 `MOMENTS` 里既有的 `risk:"bold"` 设计语言一致（高风险选项靠 `up`/`down` 的评分摆动而非成功率取胜）。

**三个选项的真实关系**（已按公式验算，非估计）：

| build | 正常体能下最优 | 体能见底时最优 |
|---|---|---|
| 射手型 SHO85 / WIL60 | 稳推 77% | 稳推 69%（不变） |
| 意志型 SHO65 / WIL85 | 等门将 71% | 等门将 69%（不变） |
| 均衡 SHO75 / WIL75 | 稳推 71% | **等门将 65%（翻转）** |

也就是说：**你的 build 极端时，答案就是你的 build**；只有均衡型球员会在体能见底时遇到真正的选择翻转。

这比「累了就该选意志」更准确也更有意思——一个伟大的射手在 120 分钟之后依然该相信自己那一脚，而这是 `COND_SENS`（SHO 0.7 / WIL 0.4）自己算出来的结果，不是单独为点球配的表。

见上表。这不是特意为点球配的平衡，是 `COND_SENS` 自己算出来的结果，测试会锁住它。

**⚠️ 推导时不要拿 `cond()` 的 clamp 边界当可达值。** 本设计初稿在这里栽过：它按 `cond` 会跌到下限 `.78` 来选常数，于是把「等门将」的截距定成 `.66`，交叉点根本不存在。实际上

```js
cond(s)=clamp(1+(s.form-55)/500+(s.fitness-72)/600,.78,1.08)
```

体能项单独最多贡献 `-0.12`，所以**体能归零、状态正常（55）时 `cond` 只到 `.88`**；要摸到 `.78` 得状态也同时归零。按 `.88` 重新解，交叉条件是两个截距之差 `δ < 1.4/300+1.3/160 ≈ .0128`，故「等门将」截距取 `.68`（与「稳推」齐平），交叉点落在体能 ≈33，两侧余量各约 2.7pp 与 1.3pp，不是刀尖上的平衡。

同一个陷阱适用于**任何**基于 `cond()` 推导的新判定：按可达区间算，不要按 clamp 边界算。

### 2.5 突然死亡

五轮打平后进入突然死亡：单次判定，权重给 WIL，一个弹窗收尾。不做多轮，避免流程冗长。

```js
const p=clamp(.46+(eff(s,"WIL")-70)/260+(hasTalent(s,"big_heart")?.06:0),.25,.75);
```

### 2.6 替换点

`wcMatchSim` 中的这行被真实点球取代：

```js
if(i>=3&&gf===ga){pen=true;won=rng()<clamp(.42+edge/40+(hasTalent(s,"big_heart")?.08:0),.18,.82)}
```

改为：平局时不再当场决出胜负，而是置 `pen=true` 并把控制权交给点球流程；胜负由点球结果写回。

### 2.7 记住那一脚

若玩家主罚未进且球队最终出局，在 `run` 上记录 `missedDecisivePenalty=true`。淘汰收尾会专门写它（见 §4.2）。

## 3. 人物固定节点

三个节点，都**不占执行点**。

| 时机 | 人物 | 立绘 | 内容 |
|---|---|---|---|
| 世预赛出线 | 父亲 | `assets/father.webp` | 上了半辈子夜班的人要去看儿子踢世界杯，他问的是「要花多少钱」 |
| 打进决赛的前夜 | 小满（分手则周骁） | `lin-xiaoman.webp` / `coach-zhou.webp` | 带取舍的微选择，见下 |
| 夺冠 / 止步 | 见 §4 | — | 收尾 |

### 3.1 决赛前夜的选择

不是白送的 buff，而是真实取舍：

- **「给她打电话」** → 状态 +5，体能 −6（睡得晚）
- **「早点睡，明天再说」** → 体能 +6，状态不变

两个都对。这落在最该纠结的时刻，符合这款游戏一贯的取舍手感。

小满关系为「分手」时换成周骁，避免尴尬。周骁版本的取舍相同（看录像 / 早睡），文案不同。

### 3.2 文案要求

遵循 `docs/事件编写格式.md` 的口吻：具体的动作与物件，不写情绪形容词。

## 4. 夺冠与淘汰

### 4.1 夺冠三段式

取代现在 `wcFinish` 里的单个弹窗：

1. **终场哨** —— 你跪在草皮上，队友从四面八方扑过来
2. **颁奖台** —— 手碰到奖杯之前的那半秒
3. **看台** —— 你在人群里找那两张脸

机制：
- `s.flags.worldChampion=true`
- 保留现有的荣誉条目、`fame+25`、`unlock("world_cup")`
- 生涯积分加成
- **退役结局为它单独写一段**（`buildEnding`）
- 不动 `seasonAwardCheck`（金球奖）的现有平衡

### 4.2 淘汰两段式

大多数玩家的世界杯记忆会是**输**。把它写好，比把夺冠写好更影响整体观感。

1. **终场** —— 具体的一个动作，不是概括
2. **人物收尾** —— 谁在等你

分支：
- `run.missedDecisivePenalty` 为真时，收尾专门写那一脚
- 四年后能否再来，取决于届时年龄（`ageInfo(s).age+4` 与 `diffOf(s).retireAge` 比较）

淘汰路径**必须**产出人物场景，不能是空收尾——这是本节的验收标准。

## 5. 不做什么（YAGNI）

- **不接入 `MOMENTS`**。世界杯比赛加关键时刻是最大杠杆，但要把世界杯搬到 `pendingMatch` 引擎上，属于独立一轮。
- **不给小组赛加基调选择**。同上。
- **不动金球奖平衡**。夺冠的分量通过生涯标记与结局文本体现。
- **不做多轮突然死亡**。一次判定收尾，避免流程冗长。

## 6. 测试

1. **点球状态可序列化**：`JSON.stringify(JSON.parse(JSON.stringify(shootout)))` 与原值相等（仿现有的「待决比赛必须能存档」）
2. **刷新可恢复**：`wcRun` 不再被读档清空；带 `shootout` 的存档 round-trip 后能继续
3. **WIL 决定主罚轮次**：WIL 80/65/40 分别对应第 5/3/1 轮
4. **体能敏感度**（锁住那条自然长出来的性质）：
   - `fitness=20` 时，WIL 选项成功率的**跌幅**小于两个 SHO 选项
   - **均衡 build（SHO=WIL=75）**：正常体能下「稳推」最优，体能见底时「等门将」反超
   - **射手型（SHO85/WIL60）**：两种体能下「稳推」都最优——极端 build 不该被体能翻盘
5. **点球结果写回胜负**：平局进点球后，`won` 由点球比分决定，且 `run.results` 里该场标注 `pen:true`
6. **夺冠置位**：`flags.worldChampion`、荣誉条目、结局文本包含世界杯
7. **淘汰不空收尾**：淘汰路径产出至少一个带立绘的人物场景
8. **踢飞被记住**：玩家主罚未进且出局时，`missedDecisivePenalty` 为真且收尾文案引用它
