# 赛程系统 / 属性映射 / 国家队大赛（世界杯 + 亚洲杯）

日期：2026-08-03

## 问题

五条反馈，归成三块：

1. 主界面看不到下一场比赛的对手和时间
2. 没有地方能看赛季日程
3. 「结束本月」后直接进关键时刻，没有赛前预告；月度小结的位置也不对
4. 月度事件里「媒体风险」「球探+9」这类属性不接任何东西，是空转
5. 世界杯一闪而过——世预赛一屏出积分，然后出局或晋级，毫无参与感；而且四年一届，中间太枯燥

根因分别是：**没有赛程这个数据结构**（1/2/3）、**有一批只写不读的字段**（4）、**世预赛是一次性模拟、决赛圈的进球是骰子掷的、国家队日历四年才热闹一次**（5）。

## 第一节 · 赛程系统

### 现状

对手是月末现抽的：`prepareMatch` 里 `opts.opponent||pick(opponentPool(s))`（app.js:958），`shouldPlayMatch`（app.js:1351）当场决定这个月有没有比赛。所以「下一场是谁」这个信息在系统里根本不存在，1/2/3 全部卡在这里。

### 新增状态

```js
s.schedule = {
  season,                    // 生成时的赛季
  clubKey,                   // 生成时的俱乐部名
  nationalCalled,            // 生成时是否已被征召
  fixtures: [{
    month,                   // 绝对月份 totalMonth
    type,                    // "club" | "national" | "wcq" | "wcfinals" | "award"
    opponent, strength, home,
    competition,             // "中超第3轮" / "世预赛第2轮" / "世界杯决赛圈"
    status,                  // "upcoming" | "played" | "missed"
    result                   // null | {gf, ga, goals, assists, rating}
  }]
}
```

`fixtures` 按 `month` 升序。`missed` 表示该场因伤停或雪藏没打——**日程上要留痕**，不能静默消失，否则玩家会以为赛程错了。

### 生成

`buildSchedule(s, rng)`：

- 比赛月份沿用 `shouldPlayMatch` 的节奏：`age<16` 每3月，`campus` 每2月，其余每月。**这个规则从此只有一处定义**，`shouldPlayMatch` 改为查 `s.schedule`
- 对手从 `opponentPool(s)` 不重复抽满一季；池子不够长就允许循环，但同一对手不相邻
- 主客交替
- 叠加国家队友谊赛：`national.called` 时每6个月一场
- 叠加世预赛与世界杯（见第三节）
- 叠加赛季评选：每赛季最后一个月

`ensureSchedule(s)` 在 `advanceMonth` 和 `renderAll` 开头调用。当 `season` / `clubKey` / `nationalCalled` 与当前不符时重建，**只重建 `month > s.totalMonth` 的条目**——已打过的比分必须保留，否则转会会抹掉半个赛季的战绩。

### 主界面

`now-strip`（index.html:130）插一条下一场信息：

```
● 职业生涯 · 每月3个执行点   下一场 · 客场 vs 山东泰山 · 本月末      [结束本月]
                            下一场 · 主场 vs 日本（世预赛第3轮）· 还有2个月

```

移动端 `.now-strip span:not(.live-dot){display:none}`（style.css:16）会把它藏掉，需要为这条新信息单开一个不被该规则命中的元素。

### 日程页

不新增第10个导航按钮。现有「比赛」tab（`renderMatches`，app.js:1713）只有一个归档列表，扩成「赛程」：

- 顶部 hero：本赛季已打/总场次、进球、胜率
- **本赛季日程**：一行一场，已打显示比分与评分，未打显示对手+主客+赛事，当前月高亮
- 下方保留「最近比赛」归档

### 比赛流程

```
结束本月
  ├ 赛前预告 modal  ── 对手 / 主客 / 实力差 / 你的体能状态 / 预估首发率 / 赛季目标与教练挑战进度
  │                    三个选项 = 专注禁区 / 回撤组织 / 疯狂逼抢，点选后写入 s.matchPlan
  ├ prepareMatch(s, rng, {opponent, home, plan, competition})   ← 预告点完才调用
  ├ 关键时刻 ×2      （已有）
  ├ 比赛简报         （已有）
  ├ 本月事件 / 剧情 / 征召 / 评选 / 教练挑战
  └ 月度小结         ← 移到队尾
```

行动页的「本场职责」保留为**默认值**，预告屏预选中它。

预告屏的预估首发率直接用 `prepareMatch` 里那条 `rawStart` 公式的 `clamp(rawStart,.15,.9)`——它不含随机项，可以在不掷骰的情况下算出来。**这个公式从此要抽成 `startChance(s, opts)` 供两处调用**，不能在预告屏抄一份。

### 必须一起修的顺序 bug

`finishMonth`（app.js:1626-1627）现在是：

```js
modalQueue.unshift(月度小结)
if(ctx.matchReportModal) modalQueue.unshift(简报)
```

两个都插队首，而本月的事件走 `enqueueDecision` → `push`。结果队列是 `[简报, 月度小结, 事件A, 事件B…]`——**月度小结排在了本月事件前面**。

而且小结的 body 是 `finishMonth` 执行时就拼好的字符串，那时事件还没被玩家点开，**事件造成的属性变化拿不到**。

改法两步：

1. 小结改 `push` 到队尾 → `[简报, 事件A, 事件B…, 月度小结]`
2. 小结 body 改惰性求值。`pumpModal` 里 `options` 已经支持函数（`typeof d.options==="function"?d.options(S):d.options`，app.js:1307），body 照抄一行：`$("modalBody").innerHTML=(typeof d.body==="function"?d.body(S):d.body)||""`

这样月度小结才真的是这个月的总账。

### 存档

**不升 VERSION。** `loadGame` 是 `if(data.version!==VERSION)return null`（app.js:1299），升版号等于清掉所有人的存档。改在 `normalizeSave` 里补 `if(d.schedule===undefined)d.schedule=null`，下次 `ensureSchedule` 自动重建。

## 第二节 · 属性映射

### 现状盘点

| 字段 | 实际被读的地方 | 事件写入 |
|---|---|---|
| `study` | **无** | 2 |
| `risks.health` | **无**（只写不读） | 4 |
| `scout` | 仅 `routeChoice16` / `setRoute` 的16岁门槛 | 6 |
| `language` | 仅 `enterProAt18` 的海外晋升门槛 | 4 |
| `risks.media` | 仅 `riskSettlement` 一条隐形随机扣分 | 6 |
| `family` | 仅3个事件的触发条件，无数值作用 | 33 |

### 处理

| 字段 | 处理 | 落点 |
|---|---|---|
| `study` | 删 | → `WIL`（补功课＝自律） |
| `risks.health` | 删 | → `s.injury.risk` |
| `scout` | 删 | → `fame`，等量搬运 |
| `risks.media` | 删 | → `fame` 即时负向 |
| `language` | 收窄 | 保留16→18门槛；`english` 行动 `phases` 去掉 `"pro"`；18岁后写它的事件改写 `WIL`/`form` |
| `family` | 保留并接真作用 | `familySupport()` 抬 form 基线 + 侧栏第4根条 |

`健康风险 → injury.risk` 是白捡的：`prepareMatch` 的伤病公式已经在读 `(s.injury.risk||0)/900`（app.js:996），语义完全对得上，接过去当场生效。

同时删掉 `riskSettlement` 里那条「`risks.media>=65` 每月20%概率 `fame-8`」（app.js:1322）——玩家看不见的骰子不该存在。`risks` 只剩 `gambling`。

事件的**效果标签文本**要同步改：`"球探+9，状态+5；感情-10"` → `"声望+9，状态+5；感情-10"`。数值改了标签没改，比不改更糟。

### family 接 form 基线

必须按基线写，不能写成每月固定 `+N`。app.js:1592 那段注释已经踩过这个坑：form 每月按 22% 回归基线，固定 `+N` 会把均衡点顶高 `N/0.22≈4.5N`。照抄 `loveSupport`（app.js:766）的分档形状：

```js
function familySupport(s){const f=s.family;return f>=90?4:f>=70?2:f>=50?1:f>=30?0:-3}
const base = 52 + loveSupport(s) + familySupport(s) + (house?2:0);
```

family 初始 86 落在 `+2` 档，上有 `+4` 下有 `-3`，两头都够得着。那33个写 family 的事件一行不用改。

侧栏新增家庭条要注意 `tests/structure.test.mjs:866` 的孤儿配色护栏：`.mini-track.<色>` 定义了就必须有地方引用，`style.css` 与 `index.html` 的 `class` 要一次改齐。

### 两个必须实测标定的数

**1. 16岁分流的后门阈值。** 今天是 `overall>=63+d.threshold || scout>=28+d.threshold`（app.js:1088）。scout 起始5、事件给 +4/+8/+9/+18/-6/-10；fame 起始3，除事件外还从每场比赛拿 `goals*1.3+assists*.7+(rating>=8?2:0)`（`applyMatch`）。两条曲线形状不同，**把 28 直接抄成 fame 阈值必然错**。

方法：用现有无头驱动跑足量局数，量出今天 `scout>=28+d.threshold` 的通过率，反解新的 fame 阈值，使后门宽度不变。`setRoute` 里的 `scout>=38+d.threshold` 同样处理。

**2. 在飞存档的搬运。** 不升 VERSION，所以 `normalizeSave` 要把老档已积累的 scout 折进 fame（`d.fame += (d.scout||5)-5`）再删字段。否则一个练了一年球探的档会在16岁突然撞墙。

## 第三节 · 国家队大赛（世界杯 + 亚洲杯）

### 大赛日历

世界杯四年一届，中间两年只剩每半年一场友谊赛，空得发慌。加入亚洲杯填中间：

| 排期 | `totalMonth` | 年龄 |
|---|---|---|
| 亚洲杯 | `%48===24`，且 `>=72` | 20 / 24 / 28 |
| 世预赛 6轮 | 世界杯月 −12 起每2月一轮 | 21 / 25 / 29 |
| 世界杯 | `%48===0`，且 `>=96` | 22 / 26 / 30 |

23 / 27 岁留空——只有友谊赛。**这是刻意的**：这游戏的主干是俱乐部生涯，如果每年都有大赛或预选赛，国家队反而不再是高光，而变成负担。亚洲杯不设预选赛（中国队亚洲杯从不缺席），也正好让两条线错开。

首届亚洲杯卡在 `>=72`（20岁），但 `nationalSelectionCheck` 的征召门槛通常要综合 74 左右，多数存档的第一届会是 24 岁那次——与世界杯 `>=96` 的处理一致，不额外补偿。

### 亚洲杯：与世界杯同规模，难度靠对手池自然分层

7 场：小组 3 场 + 十六强 + 八强 + 半决赛 + 决赛，一个月内打完，每场 1 个关键时刻，流程与世界杯决赛圈完全一致。

**不给亚洲杯任何难度偏移**——用同一套 `cupMatchSim` 判定。夺冠概率的差别完全来自对手池：世界杯淘汰赛池 84~93（巴西93/法国93/阿根廷92…），亚洲池最强的日本才 85。同一个综合 90 的球员，中国队实力 87，在亚洲杯淘汰赛里略占优，在世界杯淘汰赛里是下风。**世界杯冠军仍是幻想，亚洲杯冠军在综合 90 上下变成够得着的目标**——这是从实力表里自然长出来的，没有在判定里加任何补正。

对手池不新增数据，从现有 `WC_QUAL_POOL`（亚洲区11队）按强度分层派生，保持亚洲球队强度只有一处定义：

```js
// WC_QUAL_POOL 更名 ASIA_POOL：世预赛用全池，亚洲杯按强度分层
const AC_GROUP_POOL = ASIA_POOL.filter(t => t.strength < 78)   // 卡塔尔76 伊拉克73 阿联酋72 阿曼69 越南67 巴林66
const AC_ELITE_POOL = ASIA_POOL.filter(t => t.strength >= 78)  // 日本85 韩国83 伊朗82 澳大利亚80 沙特78
```

小组赛抽弱队、淘汰赛抽强队，和世界杯的 `WC_GROUP_POOL`/`WC_ELITE_POOL` 结构对齐。`AC_ELITE_POOL` 只有5支而淘汰赛要4轮，正好够且每届阵容不同。

新增：`s.national.asianCups` 计数、荣誉 `{title:"亚洲杯冠军", icon:"亚"}`、成就 `{id:"asian_cup", icon:"亚", name:"亚洲之巅", desc:"赢得亚洲杯"}`。

### 通用赛事引擎：不许复制粘贴

亚洲杯和世界杯决赛圈结构完全同构（7阶段、小组出线、淘汰赛基调三选一、平局进点球、夺冠/淘汰收尾）。现在这套逻辑散在 `wcDraw`/`wcNext`/`wcKnockoutChoice`/`wcPlayMatch`/`wcShootoutStep`/`wcFinish`/`wcMatchSim`/`resumeWorldCup` 约200行里。

**照抄一份改个名字是不可接受的**——这正是本 spec 在 `resolveMoments` 那里已经拒绝过的错误。改为参数化：

```js
s.national.cupRun = {                 // 由 wcRun 更名
  cup: "world" | "asian",             // 新增：赛事类型，分派配置用
  moments, choices,                   // 新增：关键时刻的中断恢复
  stage, group, ko, results, groupWins, groupPts, alive, shootout, ...   // 原样保留
}
```

按 `cup` 分派的只有一张配置表：对手池、阶段名、荣誉标题、成就 id、决赛前夜与收尾场景的文案。判定、点球、出线规则、中断恢复全部共用。

配套要改的三处：

- **`wc*` 一律更名 `cup*`**：`wcDraw`/`wcNext`/`wcKnockoutChoice`/`wcPlayMatch`/`wcShootoutStep`/`wcFinish`/`wcMatchSim`/`wcOutroScene`/`wcFinalEve`/`resumeWorldCup` → `cupDraw`/`cupNext`/…/`resumeCup`。留一半旧名字比全不改更糟
- 这些函数**有一半挂在 `API` 导出上**（app.js:1753），`tests/structure.test.mjs` 直接按名字调用。改名要连测试一起改，不能靠加别名糊过去
- 天赋「决赛先生」`final_master` 的描述是「世界杯决赛表现获得额外加成」，现在也要覆盖亚洲杯决赛。描述改成「大赛决赛」，`cupMatchSim` 里 `i===6` 的判定不变（两个赛事的决赛都是 stage 6）

### 世预赛：从一屏幻灯片摊成一整年

`simulateQualifiers`（app.js:1367）在一个月里掷完8场，积分由 `overall(s)` 推出来的球队实力算出，玩家不在场上、没有任何选择。

改为排进赛程：

```
世界杯月：totalMonth = 96 / 144 / 192（22 / 26 / 30 岁）
世预赛 6 轮：84, 86, 88, 90, 92, 94，每两月一场
这6个月国家队比赛「取代」当月俱乐部比赛
每轮流程与俱乐部比赛一致：预告（基调三选一）→ 关键时刻×2 → 简报
你的进球直接进比分 → 进积分 → 决定出线
```

摊开后世预赛跨越6个月，进度必须存档。新增：

```js
s.national.wcQual = {
  wcMonth,            // 目标世界杯的 totalMonth，用于判断这轮属于哪一届
  rounds,             // 排定的轮次总数（中途征召会少于6）
  played,             // 已打轮数
  points,             // 累计积分
  threshold,          // 出线线，按 rounds 折算后固定下来
  results: [{opp, gf, ga, goals, assists}],
  settled             // 是否已出过出线/出局判定
}
```

`startWorldCup` 从「一次性跑完」拆成两半：`scheduleQualifiers(s)`（在世界杯前一年的年初建 fixtures 和 `wcQual`）与 `settleQualifiers(s)`（最后一轮打完后判定出线，接抽签或出局场景）。

出线线按6场重算：今天8场需 `11+d.threshold` 分（11/24≈0.458），6场18分同比例约 `8+d.threshold`。

**中途才被征召要按已打轮数比例折算**：月90首次征召只剩3轮，阈值同比缩到约 `4+d.threshold`。否则新晋国脚必然出局。

出局不能再是一句「差一口气，四年后再来」——那是把玩家整整一年的投入一笔带过。要一个和夺冠场景等重的出局场景。

### 决赛圈：让进球是你选的（两个赛事共用）

- **每场加 1 个关键时刻**，复用 `MOMENTS` / `momentOptions` / `momentSuccessRate`
- **小组赛也给基调三选一**：`wcNext`（app.js:1539）现在写死 `wcPlayMatch(s,"均衡")`，把 `wcKnockoutChoice` 推广到全部 stage

### 关键时刻并入比分：复用而非重写

`finishMatch`（app.js:1008-1040）的并入规则比「成功就 `gf++`」严得多：

```js
const claimGoal = bold => {
  if(p.goals < p.gf){ p.goals++; return true }        // 先认领模型已算出的进球
  if(bold && overflow < 1){ overflow++; p.gf++; p.goals++; return true }  // 只有高风险能凭空造球
  return false                                         // 否则 denied，评分收益减半
}
```

即：**稳妥选项只能把球队已有的进球认领到自己名下，只有高风险选项能创造 xG 之外的进球，且每场至多一个 `overflow`**。失败且 `risk==="bold"` 时另有 35% 概率 `ga++`（对手反击）。

世界杯不能重写一套近似规则——两套会漂移。做法：

**把 `finishMatch` 里的关键时刻结算块抽成 `resolveMoments(s, p, rng)`**，输入输出是 `{gf, ga, goals, assists, keyWins, failures, timeline, moments, choices, oppStrength}` 这个形状，由 `finishMatch` 和世界杯路径共同调用。这是本次改动的直接需要，不是顺手重构。

**世预赛更进一步：直接走完整的 `prepareMatch`/`finishMatch` 管线。** `prepareMatch` 现在用 `currentClub(s)` 取球队，给它加一个 `opts.club` 覆盖（`{name:"中国", strength:<国家队实力>}`）即可。这样世预赛白拿预告、首发判定、时间线、评分、伤病、简报全套，不用平行实现一遍。

决赛圈保留 `cupMatchSim`（由 `wcMatchSim` 更名，它有基调系数和赛事阶段加成），只把关键时刻通过 `resolveMoments` 并进去。亚洲杯与世界杯走同一条路径。

### 日程整合

三种大赛**都提前出现在日程页**——这是第一节白送给第三节的东西。玩家在赛季开始就看见「第9月 · 世预赛第3轮 · 客场 vs 日本」或「第6月 · 亚洲杯」，会为它提前调体能、攒状态。这份提前量本身就是参与感，比任何过场文案都管用。

主界面在大赛年额外显示「亚洲杯还有 N 个月」／「世界杯还有 N 个月」。

### 存档兼容

`resumeWorldCup`（app.js:1465）已经能把进行中的赛事接回来，改名 `resumeCup` 后读 `cupRun`。新增的世预赛轮次是普通 fixture，靠 `s.pendingMatch` 恢复，与俱乐部比赛同一条路径。

`cupRun` 相比 `wcRun` 多两个字段：`cup`（赛事类型）、`moments`/`choices`（关键时刻的中断恢复）。

**`wcRun → cupRun` 改名必须在 `normalizeSave` 里迁移**，否则一个正打到半决赛的存档会在更新后凭空丢掉整届赛事——而且因为不升 VERSION，它不会被清档，而是变成一个 `cupRun` 为空、`wcRun` 还挂着的僵尸状态：

```js
if(d.national && d.national.wcRun && !d.national.cupRun){
  d.national.cupRun = {...d.national.wcRun, cup:"world"};
  delete d.national.wcRun;
}
```
