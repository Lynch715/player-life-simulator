# 联赛积分榜

日期：2026-08-07

## 问题

玩家想看到自己球队在联赛里排第几。现在没有任何地方能看到——比赛打完只有一份简报，赛季末直接跳出「你拿了冠军」或者没拿，中间的过程完全是黑箱。

更糟的是**联赛冠军现在是掷骰子判的**（`seasonAwardCheck`）：

```js
leagueTitle = ss.matches>=7 && ss.wins/ss.matches>=.7
              && overall(s)>=currentClub(s).strength-2
              && rng()<.48-diffOf(s).threshold*.02;
```

满足前三个条件后再掷一次 48% 的骰子。也就是说两个赛季表现一模一样，一个拿冠军一个没拿，玩家无从理解。

## 实测到的现状

| 联赛 | 玩家一季的轮次 | 参赛队总数（含玩家） |
|---|---|---|
| 中超梯队（14–16岁） | 3 | 16 |
| 校园联赛（16–18岁） | 5 | **11（奇数）** |
| 英超梯队（16–18岁） | 11 | 20 |
| 中超（18岁+） | 12 | 16 |
| 英超（18岁+） | 12 | 20 |

轮次由赛程决定：梯队每3个月一场、校园每2个月一场、职业每月一场（大赛月被国家队占用的除外）。

校园联赛是奇数队：玩家的「重庆市第七中学校队」不在 `CAMPUS_CLUBS` 里，10 支对手 + 玩家 = 11。

## 决定

- **压缩赛制**：全联盟就打玩家那么多轮（3/5/11/12），不模拟真实的 30/38 轮。理由：这游戏本来就是「一个月一场」的抽象节奏，让积分榜跟这个节奏对齐，玩家赢一场排名立刻动；若按真实赛制，个人贡献会被稀释到 1/3，出现「我进了两球但排名没动」的脱节感。
- **排第一就是冠军**，废掉骰子。
- **所有联赛都有**，梯队/校园/中超/英超共用一套机制。
- **放在「赛程」页顶部**，不新增导航按钮（现在 9 个在移动端已经要横向滚动）。

## 第一节 · 数据与推进

### 新增状态

```js
s.league = {
  season,      // 赛季号，翻季重建
  key,         // 联赛名 + 球队名，转会/分流时重建
  rounds,      // 本季总轮数，由赛程里 type==="club" 的场次数决定
  played,      // 已进行轮数
  teams: [ {name, strength, p, w, d, l, gf, ga, pts} ]   // 含玩家球队
}
```

### 其他球队的比分从哪来

**每轮真实配对**：玩家的对手由赛程定死，其余球队随机两两配对，逐对模拟比分。每一分都来自一场真实模拟的比赛。

否决的两个方案：

- **逐队独立掷 W/D/L**：算术上会崩——全联盟总胜场不等于总负场，进球总数也对不上。玩家一加总就会发现这榜是假的。
- **赛季末一次性生成**：赛季中途没榜可看，等于废掉了这个功能的核心价值。

### 推进时机

每次 `resolveMatch` 把玩家那场写回 fixture 之后，同一轮再把其余球队配对模拟。

- **玩家的比分直接进榜，不重算**——榜上那一行必须和赛程页、比赛简报是同一个结果，不能出现三处对不上。
- 奇数队（校园 11 队）每轮随机一队轮空，轮空不计场次。
- 配对与结果用**按「赛季 + 轮次」派生的种子**，保证读档、重渲染、切 tab 都不会让已经打完的历史比分变样。

### 两个必须写死的边界

**1. 玩家没上场时，他的球队照样要踢。**

伤停或被雪藏时 fixture 被标成 `missed`，玩家不出场——但球队不会因此弃权。这一轮仍要为他的球队模拟一个结果，只是**不带玩家的个人加成**（用俱乐部原始 strength，不叠 `atk/def` 那部分）。

不这么做的话，受伤三个月的玩家会看到自己球队的「场次」比别人少三场，榜看起来就是坏的。

**2. 只有 `type==="club"` 的场次算一轮。**

大赛月（`cup`/`wcq`/`national`）你不在俱乐部，联赛那一轮不推进。`s.league.rounds` 直接取赛程里 `type==="club"` 的场次数，两边永远对齐。

### 排序

积分 → 净胜球 → 进球数 → 队名。足球惯例。

## 第二节 · 呈现与接线

### 渲染

复用现成的 `.rank-table`（排行页在用），加 `.league-table` 变体。玩家球队那行套已有的 `tr.me` 高亮。

```
本赛季 · 中超                      第 7 轮 / 共 12 轮
──────────────────────────────────────────────────
 #  球队            场   胜平负     净胜   积分
 1  上海海港         7   5 1 1      +9     16
 …
 6  重庆铜梁龙  ←你   7   3 1 3      +1     10
```

移动端沿用 `.rank-table` 已有的列隐藏做法，只留 名次/球队/场/积分。

**梯队与校园的诚实处理**：这两个联赛一季只有 3~5 轮，名次噪声大。榜照常显示，但标题旁标注 `第2轮 / 共3轮`，让玩家知道样本就这么小，而不是以为自己「稳居第4」。

### 三处接线

1. **联赛冠军**：`seasonAwardCheck` 里那行掷骰子换成 `standings[0].name === s.club.name`。

2. **保级目标**：现在 `survive` 目标的文案是「帮 XX 至少赢下6场，**别掉进降级区**」，但游戏里根本没有降级区，判定只看 `wins>=6`。改成「赛季末不落进榜尾 3 名」，让这句话第一次有真实含义。
   **不引入真正的升降级机制**——那会牵动转会、合同、声望一整串，属于另一个话题。这里只是让目标判定对得上它自己的文案。

3. **存档兼容**：不升 VERSION（升了会清档，见 `loadGame` 的 `data.version!==VERSION → return null`）。`normalizeSave` 补 `if(d.league===undefined)d.league=null`，下次自动重建。

## 不做

- **射手榜**：需要给所有 NPC 建模个人数据，是另一个量级的工作。
- **真实升降级**：牵动转会市场、合同、声望，另开一轮。
- **跨赛季历史榜单**：赛季末结算完就丢，只留冠军进荣誉墙。
- **改动其他球队的实力值**：`CSL_CLUBS`/`PL_CLUBS` 等的 strength 保持不变。

## 验收

- `node --check app.js && node tests/structure.test.mjs` 全绿，且**连跑 30 次**（这个项目的测试有随机性，一次绿不算数）
- 新增测试：
  - 全联盟每轮的胜场数等于负场数、进球总数等于失球总数（内部自洽）
  - 玩家在榜上那一行的战绩，与赛程页 fixture 的 result 完全一致
  - 同一存档反复 `ensureLeague` / 重渲染，历史比分不变（种子确定性）
  - 校园联赛 11 队时每轮恰好一队轮空，且轮空不计场次
  - 赛季末榜首 = 拿到联赛冠军荣誉；非榜首则没有
  - `survive` 目标：榜尾 3 名内判失败，否则成功
  - 各联赛轮次与赛程里 `type==="club"` 的场次数一致（3/5/11/12）
- 长跑回归：10 局完整生涯，积分榜不崩、不残留跨赛季脏数据
- 重建单文件版 `python3 build_single.py`
